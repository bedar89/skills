### Worktree and simulator cleanup

1. Snapshot and audit. Record `df -h /`, then run `scripts/worktree-audit.sh [-b <pr-base-ref>] [repo-path]` (principle-build-the-lever). Without `-b` it checks `MERGED` against `origin/HEAD`, so pass `-b origin/<branch>` when PRs target another branch. It reads paths from `git worktree list`, never hand-typed, since a hand-typed `myrepo-worktrees/x` misses one that lives at `.cursor/worktrees/myrepo/x` (principle-encode-lessons-in-structure). It classifies each worktree by size, age, merge state, uncommitted work, PR state, and the newest chat that touched it, then suggests a bucket. The transcript scan is slow, so background it.
2. The bucket is advice, not deletion permission. `review-clean` means only that the audit observed no ordinary Git status entries. It does not prove current usage, complete content safety, or integration. Cleanup requires the repository's explicit scope, publication or discard evidence, owner release, and the complete content checks below.
3. Verify usage before deleting. Check the current worktree owner and other known runtime users. Pinned or old transcript metadata alone does not prove that a workspace is idle or active. Have the owner stop writing and release the exact workspace. Preserve an active, unknown, or unconfirmed workspace.
4. Inspect the complete contents. Untracked and ignored files are not disposable by default. Inspect tracked bytes and modes against HEAD even when index flags hide edits, and include untracked, ignored, nested-repository, submodule, and special-file contents. Ordinary `git status` alone is insufficient. Keep anything valuable or unknown unless its preservation and recovery are proven. The audit's `hold-contents`, `hold-wip`, and `hold-unknown` buckets must remain held until reconciled.
5. Recheck immediately before removal. Require integration or an explicitly approved recoverable discard, owner release, and the complete content check. Then use only ordinary `git worktree remove <exact-path>` with the path resolved from Git's worktree list. On refusal, preserve the directory and report the reason. Never force removal, delete the directory as fallback, or use `git clean`. Branch deletion has its own integration and usage check. Re-list worktrees and report retained work separately.
6. Simulators and other reclaimers. Include these only when the user explicitly requests those targets, after checking usage and consequences. Simulators are usually the next-biggest win. `xcrun simctl --set testing delete all` (XCTestDevices clones), `xcrun simctl delete unavailable`, and `xcrun simctl runtime list` then `runtime delete <id>` for old runtimes. More when needed: Xcode `DerivedData` and `iOS DeviceSupport`, `~/Library/Application Support/Cursor` (`state.vscdb.backup`, and `snapshots/roots/<root>` where a `<root>` named for a folder you opened as a workspace balloons), package caches (pnpm, uv, brew, yarn). Clear only caches the user has not said to keep.

This is the one playbook that deletes user state with no code review to catch a slip, so the gates above are the review.

**Reply:** `df -h /` before and after with space reclaimed, the worktrees pruned, and a one-line reason for each held back (in-use by which chat, or uncommitted work).
